# Админка

Два сервиса поверх существующего `server/` (прокси-сервера, который не меняется):

- `api/` — Express + Prisma (SQLite) + JWT-авторизация. Отдаёт JSON API на `:8090`.
- `web/` — Nuxt 3 (SPA). UI на `:3000`, ходит в `api/`.

## Первый запуск

```bash
cd admin/api
cp .env.example .env        # при необходимости поменять JWT_SECRET/порты
npm install
npm run migrate             # создаёт SQLite-базу и таблицы
npm run seed                # импортирует data/**/*.json в редактируемые датасеты
npm run create-superuser -- --email=you@example.com --password=ваш-пароль
npm run dev                 # API на http://localhost:8090
```

```bash
cd admin/web
cp .env.example .env
npm install
npm run dev                 # UI на http://localhost:3000
```

Прокси-сервер (`server/`) запускается отдельно как раньше (`npm run dev` там же) — админка читает
живые данные и историю через него, но не обязательна для его работы.

## Роли и доступ

- Публичной регистрации нет. Первый администратор создаётся один раз через
  `npm run create-superuser` (скрипт откажется создавать второго ADMIN без флага `--force` —
  дальше новых пользователей заводит сам admin со страницы «Пользователи»).
- `ADMIN` — видит и редактирует всё. `VIEWER` — только просмотр (сервер отдаёт 403 на попытку
  редактирования в API, независимо от того, что показывает UI).

## Редактируемые данные

Справочные датасеты из `data/**/*.json` (маршруты, остановки, станции метро, геометрия маршрутов и т.д.)
при `npm run seed` копируются в SQLite как отдельные записи — редактирование в админке не трогает исходные
файлы в `data/`. Каждый датасет — отдельный пункт меню (сгруппированы по «Наземный транспорт» / «Метро»).
Список датасетов и то, как из каждого файла получается ключ записи, — в
[`api/src/lib/collections.js`](api/src/lib/collections.js).

`npm run seed` пропускает датасет, если в базе уже есть его записи, — то есть после обновления файла
в `data/` повторный запуск ничего не перельёт. Чтобы подтянуть новые данные, нужен явный переимпорт
(коллекция удаляется целиком и заливается заново из файла):

```bash
npm run seed -- --only=ground_transport/schedule_trips --force
```

Правки, сделанные в админке для этой коллекции, при этом теряются — они живут только в базе, в
`data/` их нет. `--force` без `--only` затронул бы все датасеты сразу и поэтому требует ещё и `--yes`.

`ground_transport/route_geometry` — точная полилиния каждого маршрута (поле `points` с портала), получена
отдельным запросом к `getRoutesWithMainSubroutes.php` (та же выгрузка, что и route_stops, но без отбрасывания
геометрии) — см. `data/manifest.json`.

Транспорт в реальном времени (`/api/live/*`) и история GPS (`/api/history/*`) — read-only, это прямой снимок
состояния прокси-сервера и его NDJSON-логов.

## Карта

Страница «Карта» (Leaflet + тайлы OpenStreetMap) показывает вкл/выкл слоями: Транспорт в реальном времени (автообновление
каждые 5с), остановки наземного транспорта, станции и входы метро, а также геометрию выбранного маршрута.
В формах редактирования остановок/станций (там, где есть числовые поля `lat`/`lng`) есть мини-карта с
перетаскиваемой точкой; записи `route_geometry` показывают линию маршрута для просмотра (редактирование —
через JSON-поле `points`).

## Переезд на Postgres

Схема в [`api/prisma/schema.prisma`](api/prisma/schema.prisma) на Prisma — переезд с SQLite на Postgres
это смена `datasource.provider` на `postgresql` и `DATABASE_URL` на строку подключения, без изменений
в коде запросов.
